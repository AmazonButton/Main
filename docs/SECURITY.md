# SECURITY ARCHITECTURE & THREAT MODEL

## 1. Cryptographic Device Authentication (Edge to Cloud)

A physical IoT button transmitting an order request cannot simply send a raw `deviceId` or plaintext JSON. If unauthenticated, malicious actors could sniff packets, forge ghost orders, or deplete warehouse stock.

### Signature Formula:
$$\text{Signature} = \text{HMAC-SHA256}\Big(K_{\text{device}}, \;\; \text{DeviceId} \parallel \text{Timestamp} \parallel \text{Nonce} \parallel \text{RawBody}\Big)$$

Where:
- $K_{\text{device}}$: 256-bit symmetric secret key flashed to the ESP32's encrypted NVS and stored securely on the backend.
- `Timestamp`: Epoch milliseconds at the instant of button wake.
- `Nonce`: 32-character random hex string generated by the ESP32 hardware RNG (`esp_random()`).
- `RawBody`: Exact serialized JSON string (`{"eventType":"SINGLE_PRESS", ...}`).

## 2. Threat Vector Mitigations

| Threat | Attack Scenario | Mitigation in Platform |
|---|---|---|
| **Replay Attack** | Attacker sniffs a valid Wi-Fi packet and replays it 100 times to spam orders. | **Nonce Cache & Expiry**: The backend tracks every received `deviceId:nonce` pair. Any repeated nonce within the 120s validity window is rejected with HTTP `409 REPLAY_DETECTED`. |
| **Expired Request / Time Shift** | Attacker captures a packet and replays it hours or days later. | **Timestamp Drift Window**: The backend enforces $|T_{\text{server}} - T_{\text{device}}| \le 120\,\text{seconds}$. Older packets are discarded with HTTP `401 REQUEST_EXPIRED`. |
| **Tampered Payload** | Attacker intercepts packet and changes quantity from 1 to 50. | **HMAC Integrity**: Tampering with any byte in the body invalidates the HMAC signature. The backend calculates the expected digest and rejects with HTTP `401 INVALID_SIGNATURE`. |
| **QR Code Eavesdropping** | Attacker scans the physical QR code on the back of the button. | **Zero Secret in QR**: The QR code only contains `https://app.smartorder.vn/claim?d=BTN-001&c=CLAIM-749201`. It NEVER contains the cryptographic secret key or Wi-Fi credentials. |
| **Cross-Tenant Data Leak** | Store A attempts to view or update orders/devices of Store B. | **Strict Tenant Isolation**: Every SQL query joins and validates `storeId` against the user's authenticated JWT claims. |
| **Rapid Multiple Presses (Spam Tapping)** | Customer taps the button 6 times in 4 seconds. | **Hardware Debounce + Cloud Idempotency**: Hardware debouncer ignores repeat presses during the 3-second wake cycle. Cloud idempotency ensures identical request IDs return the existing order rather than creating duplicates. |
